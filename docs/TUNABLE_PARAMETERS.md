# Weave Tunable Parameters and Exact Code Locations

Weave exposes one unified knob space across SM103, H20 and MI308X. Every parameter below changes real host dispatch or kernel execution; the 24 historical fields that had no reader in the runtime policy ABI are removed, and the historical H20 ordering switch is no longer part of the public surface. Pipeline depth is derived at launch time from the tile shape and the remaining SMEM budget, not frozen by a public knob.

The document has three sections: **Spatial**, **Temporal** and **Implementation**. Each row carries the host parse location and the kernel consumption location. `tests/verify_tunable_params_doc.py` resolves every citation against the working tree.

## 4. API argument: shared experts

`num_shared_experts` is a Python/C++ API argument, not an environment knob. Every MegaMoE entry point defaults it to `0`; the shared-expert buffers are allocated only when it is explicitly non-zero (the gate API `bf16_mega_gate` takes it explicitly together with `use_shared_as_routed`). The unified surface keeps `0` as the default so routed-only workloads do not pay the shared-expert workspace or scheduling cost.

## 5. Values derived at launch time (not knobs)

The GEMM stage count, accumulator ring depth, TMA-store ring depth and scheduler look-ahead are computed from the live tile shape and the SMEM budget in `csrc/jit_kernels/heuristics/mega_moe.hpp`. The per-expert BM ladder is selected inside the scheduler when `WEAVE_ADAPT_BM=1`. These are derivations, not configuration inputs.
