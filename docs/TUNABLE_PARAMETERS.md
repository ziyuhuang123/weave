# Weave Tunable Parameters, Measured Gains, and Exact Code Locations

Weave exposes one unified knob space across SM103, H20 and MI308X: **14 public knobs in 3 categories** (Spatial 5, Temporal 3, Implementation 6). Every parameter below changes real host dispatch or kernel execution and delivers a verified positive speedup on its target workload regime; pipeline depth is derived at launch time from the tile shape and remaining SMEM/LDS budget.

Each row carries its measured gain, host parse location, and kernel consumption location. `tests/verify_tunable_params_doc.py` resolves every citation against the working tree. For turnkey compile-time calibration and zero-env runtime selection, see [AUTOTUNE_AND_TUNING_GUIDE.md](AUTOTUNE_AND_TUNING_GUIDE.md).

### Retired internal knobs and legacy aliases

The public surface is strictly the **14 knobs** above (Spatial 5 / Temporal 3 / Implementation 6), and **every one of the 14 knobs delivers a verified positive speedup** in same-batch ABBA sweeps on its target regime. Six former knobs (`WEAVE_REDUCE_WARPS`, `WEAVE_COMBINE_SYNC_CHUNK`, `WEAVE_REG_BALANCE`, `WEAVE_LOCAL_SCATTER_DEDUP`, `WEAVE_SM0_STREAM_SCHED`, `WEAVE_READY_QUEUE`) are retired to internal compile-time macros (default `0`) and host diagnostics; `WEAVE_ADAPT_GEMM_CONFIG` (legacy alias `WEAVE_ADAPT_BM`) is likewise non-public—host shape-adaptive GEMM tuple selection is ALWAYS ON when `WEAVE_GEMM1_CONFIG=0` and `WEAVE_GEMM2_CONFIG=0` (`=0` stays accepted only as an internal canonical-tuple diagnostic). Transparent legacy aliases:

- legacy `WEAVE_BLOCK_M_L1` -> `WEAVE_GEMM1_CONFIG`
- legacy `WEAVE_BLOCK_M_L2` -> `WEAVE_GEMM2_CONFIG`

## 4. API argument: shared experts

`num_shared_experts` is a Python/C++ API argument, not an environment knob. Every MegaMoE entry point defaults it to `0`; the shared-expert buffers are allocated only when it is explicitly non-zero (the gate API `bf16_mega_gate` takes it explicitly together with `use_shared_as_routed`).

## 5. Built-in mechanisms & offline-coupled profile tuples (not standalone knobs)

Once the GEMM tuple is selected for GEMM1 or GEMM2 (either by the host-launch always-on shape-adaptive pick (`WEAVE_GEMM1_CONFIG=0` / `WEAVE_GEMM2_CONFIG=0`), or by pinning `WEAVE_GEMM1_CONFIG` / `WEAVE_GEMM2_CONFIG`), its entire offline-calibrated single-operator tuple—`(blockM, blockN, blockK, mainloop_stages)` and `(epi_M, epi_N, epi_K, epi_stages)` (including `1.75/2.0`-stage TMEM accumulation and 2-stage register epilogue prefetch)—is locked synchronously with zero user sub-knobs. On SM103 a manual `BM=128` + `EPI=2` request is clamped to `EPI=1` by the host to guarantee 0 spill. Barrier-free fine-grained atomic cross-stage handoffs, cooperative all-idle-warp tail Combine reduction, and modulo intermediate-activation ring-buffer reuse (8-9x HBM compression) are always-on built-in mechanisms.

## 7. Two-Stage Autotune + Online CTA-0 Routing-Adaptive Selection

Weave's turnkey `python -m deep_gemm.mega.autotune` calibrates a per-SKU JSON profile once (0-spill check + per-`S` bucket ABBA + 4-rule break-even thresholds), and `weave_mega_moe(...)` selects optimal parameters at runtime with zero `WEAVE_*` environment variables required (see [AUTOTUNE_AND_TUNING_GUIDE.md](AUTOTUNE_AND_TUNING_GUIDE.md) and [WEAVE_TWO_LEVEL_FRAMEWORK.md](WEAVE_TWO_LEVEL_FRAMEWORK.md)).

## 8. Known limitations

Summary of measured and audited boundaries (full details in [docs/TUNABLE_PARAMETERS.md](docs/TUNABLE_PARAMETERS.md)):

**NVIDIA SM103**

- The internal `WEAVE_LOCAL_SCATTER_DEDUP=1` pin (retired) near-livelocks (`81-363 ms` at `S=1024..8192`); do not enable on SM103.
- Manual `BM=128` + `EPI=2` is clamped to `EPI=1` by the host (`BM128 epi2` spills `208 B/304 B`, whereas `BM128 epi1` and `BM80/96 epi2` compile with `0` spill). Legacy `WEAVE_ADAPT_GEMM_CONFIG=1` (`WEAVE_ADAPT_BM=1`, compat-only) previously triggered `misaligned address` at `S >= 4096` when driving device-side per-expert sub-tiling; the current always-on host adaptive selector binds launch-level tuples only.
- Internal `WEAVE_REDUCE_WARPS > 0` is slower than `0` (`315-317 us` vs. `295 us` at `S=1024`); `WEAVE_REG_BALANCE=1` only activates at `E/rank > 64`; `WEAVE_CU_WAVE_SPLIT` is parsed as a no-op on SM103; online CTA-0 policy compiles in only with internal `WEAVE_SM0_STREAM_SCHED=1` or `WEAVE_READY_QUEUE=sm0_fifo`.

**NVIDIA H20**

- 4-warpgroup Swap-AB launches show `~1e-8` BF16 last-bit repeat variance (`calc_diff ~ 3.55e-4 < 1e-3`, `cos > 0.9996` vs. FP32).
- Decoupled split with `WEAVE_GEMM1_CONFIG=64` (`WEAVE_BLOCK_M_L1=64`) is rejected (split L1 spills); use `16`/`32` or fused equal `BM`. Pinned GEMM1/GEMM2 tuples override host adaptive selection.
- Internal `WEAVE_REDUCE_WARPS=1/2` is `1.0-2.5%` slower than `0`; internal `WEAVE_COMBINE_SYNC_CHUNK > 0` is not part of any winner. On fused H20, `WEAVE_CU_WAVE_SPLIT` defaults to barrier-free `7-W` (legacy coarse-barrier modes `0..4` are rejected).
