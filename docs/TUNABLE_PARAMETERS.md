# Weave Tunable Parameters Reference

Weave exposes one unified **14-knob surface across 3 orthogonal axes** (Spatial 5, Temporal 3, Implementation 6) shared across NVIDIA SM100/SM103, NVIDIA H20, and AMD MI308X. When left at `0` (`auto`), parameters are chosen automatically by the offline hardware profile and online routing-adaptive cost model (see [AUTOTUNE_AND_TUNING_GUIDE.md](AUTOTUNE_AND_TUNING_GUIDE.md)).

## 4. Coupled per-operator pipelines and built-in handoffs

Selecting `WEAVE_GEMM1_CONFIG` or `WEAVE_GEMM2_CONFIG` (either automatically from `(M_expected, N, K)` at `0`, or via an explicit tuple `BM[:STORE_BM[:BK[:STAGES[:EPI]]]]`) locks the paired `(blockM, blockN, blockK, mainloop_stages)` and multi-stage epilogue register pipeline (`EPI = 1..4`) for each GEMM independently. Cross-stage tile arrival counters (`Dispatch -> GEMM1`), intermediate tile-ready bitmaps/rings (`GEMM1 -> GEMM2`), multi-stage `reg` / `smem` / `hbm` scatter handoffs, and per-token (`k/k`) acquire-ready all-warp Combine reduction are always enabled.

## 5. Hardware support summary

| Parameter group | SM103 (`fp8xfp4` / `fp4xfp4`) | H20 (`fp8`) | MI308X (`fp8`, EP8 & EP16) |
|---|---|---|---|
| Spatial: cross-SM/CU subsets (`DISPATCH_ACTIVE_SMS`, `SCATTER_ACTIVE_SMS`) | yes | yes | yes |
| Spatial: intra-SM/CU warp/wave ratios (`DISPATCH_WARPS`, `SCATTER_WARPS`) | yes | yes | yes |
| Spatial: `CU_WAVE_SPLIT` | accepted (no-op) | yes (expert-stream lead) | yes (`0-8` / `4-4` / `8-0`) |
| Temporal: `V_HEAD`, `READY_GROUP_SIZE`, `SCATTER_OWNER` | yes | yes | yes |
| Implementation: `PRECISION_MODE`, `GEMM1_CONFIG`, `GEMM2_CONFIG` | yes (full tuple, `EPI=1..4`) | yes (independent `BM`) | yes (independent `BM`) |
| Implementation: `REG_PULL_BYTES`, `DEDUP_MODE`, `SCATTER_STAGING` | yes (`reg` / `smem` / `hbm`) | yes (`reg` / `smem` / `hbm`) | yes (`REG_PULL_BYTES=8192`) |
